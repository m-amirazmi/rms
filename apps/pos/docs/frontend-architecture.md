# POS Frontend Architecture

> Feature-based folder structure for the POS application.

---

## Philosophy

- **Routes are thin** — only TanStack Router wiring. No business logic.
- **Features are self-contained** — each feature owns its components, types, schemas, API, and utils.
- **Shared code lives in `components/`** — reusable layout components like `AuthTopbar`.
- **No cross-feature imports** — features communicate via router navigation or localStorage, not direct imports.

---

## Folder Structure

```
apps/pos/src/
├── features/               # Feature modules
│   ├── select-staff/
│   ├── new-device/
│   └── select-category/
│
├── routes/                 # TanStack Router file-based routes
│   ├── (auth)/
│   └── (wizard)/
│
├── components/             # Shared components (AuthTopbar, etc.)
├── main.tsx
└── routeTree.gen.ts        # Auto-generated by TanStack Router
```

---

## Feature Module Anatomy

Every feature under `features/` follows this structure:

```
features/<feature-name>/
├── README.md               # Feature documentation
├── index.ts                # Barrel export — public API
├── types.ts                # TypeScript interfaces
├── constants.ts            # Mock data, magic numbers
├── schemas.ts              # Zod validation schemas
├── api.ts                  # Async functions (mock or real)
├── utils.ts                # Pure helper functions
└── components/
    ├── <feature-name>-page.tsx   # Main page component
    └── ...                       # Sub-components
```

### Rules

1. **Import from `index.ts` only** — external code never deep-imports into a feature.
2. **Route files import from features** — routes are pure wiring.
3. **Types use `import type`** — required by `verbatimModuleSyntax`.
4. **No `hooks/` folder unless reused** — hooks live inside the component that uses them. Extract only when shared across components.

## Example: Adding a New Feature

```bash
# 1. Create feature folder
mkdir -p src/features/my-feature/components

# 2. Create files
touch src/features/my-feature/index.ts
touch src/features/my-feature/types.ts
touch src/features/my-feature/schemas.ts
touch src/features/my-feature/api.ts
touch src/features/my-feature/components/my-feature-page.tsx

# 3. Create route
mkdir -p src/routes/(wizard)
touch src/routes/(wizard)/my-feature.tsx
```

Route file (`src/routes/(wizard)/my-feature.tsx`):

```tsx
import { createFileRoute } from "@tanstack/react-router"
import { MyFeaturePage } from "@/features/my-feature"

export const Route = createFileRoute("/(wizard)/my-feature")({
  component: MyFeaturePage,
})
```

---

## Shared Components

Components used by multiple features live in `src/components/`:

| Component | Used By |
|---|---|
| `AuthTopbar` | `select-staff`, future wizard steps |
| `Header` | Main app shell (post-auth) |

Features may import shared components. Shared components must never import features.

---

## Dependency Direction

```
routes/          → features/
features/        → components/
features/        → @workspace/ui/
components/      → @workspace/ui/
```

No arrow goes from `features/` → `features/` or `components/` → `features/`.
